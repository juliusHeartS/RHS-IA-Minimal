# Plan de Integración Profunda: Continue ↔ Positron

**Fecha:** 2026-06-10
**Rama:** `rhs-assistant-ops-extension-continue`
**Objetivo:** Continue desplaza a Positron Assistant y utiliza todo el potencial de Positron (runtime, consolas, plots, variables).

---

## 1. Estado Actual (Funciona)

- ✅ Continue carga automáticamente en Positron
- ✅ Continue responde preguntas de chat
- ✅ Context Bridge provee snapshot de estado de Positron (lectura)
- ✅ Commit respaldado: `6abe6f698`

## 2. Problemas Actuales (No Funciona)

- ❌ Código R/Python va al terminal genérico, no a la Consola de Positron
- ❌ No crea sesiones de runtime (R/Python) a través de Positron
- ❌ Gráficos no van al panel Plots de Positron
- ❌ Continue no puede leer variables del entorno de Positron
- ❌ Continue no sabe qué sesiones de R/Python están activas

## 3. Arquitectura Objetivo

```
Usuario: "ejecuta este código R"
    ↓
Continue GUI → core.ts → runTerminalCommand
    ↓
[INTERCEPTAR] Detectar Positron
    ↓
positron.runtime.executeCode(language, code)
    ↓
Consola de Positron → Sesión R activa
    ↓
Salida + Gráficos → Positron Plots / Variables
    ↓
Resultado vuelve a Continue como ContextItem
```

## 4. Archivos a Modificar en Continue

| Archivo | Cambio |
|---------|--------|
| `continue/extensions/vscode/src/VsCodeIde.ts` | Detectar Positron (`ideType: 'positron'`). Extender `runCommand()` para usar `positron.runtime.executeCode()` cuando esté disponible. |
| `continue/core/tools/implementations/runTerminalCommand.ts` | Interceptar ejecución. Si estamos en Positron, usar API de runtime en lugar de `child_process.spawn()`. |
| `continue/extensions/vscode/src/terminal/terminalEmulator.ts` | Si Positron está activo, redirigir salida a `positron.console` en lugar de emulador interno. |
| `continue/core/context/providers/PositronContextProvider.ts` | (Ya existe en bundle) Expandir para incluir variables dinámicas de sesiones activas. |

## 5. API de Positron a Utilizar

```typescript
// Ejecutar código en consola
positron.runtime.executeCode(languageId, code, focus, allowIncomplete)

// Obtener sesiones activas
positron.runtime.getActiveSessions()

// Escuchar eventos de sesión
session.onDidChangeRuntimeState()
session.onDidReceiveRuntimeMessage()

// Variables (si disponible)
session.listVariables()

// Plots
positron.plot (eventos de nuevo plot)
```

## 6. Estrategia de Implementación

### Fase 1: Detección de Positron
- Modificar `VsCodeIde.getIdeInfo()` para detectar Positron
- Exponer flag `isPositron` al core de Continue

### Fase 2: Interceptar Ejecución
- En `runTerminalCommand.ts`, verificar `isPositron`
- Si es Positron: usar `positron.runtime.executeCode()`
- Si no: fallback a `child_process.spawn()`

### Fase 3: Capturar Salida
- Suscribirse a `onDidReceiveRuntimeMessage` de la sesión
- Convertir salida a formato que Continue espera (ContextItem)

### Fase 4: Gráficos
- Interceptar eventos de plot de Positron
- Convertir a `imageUrl` base64 para Continue

### Fase 5: Variables
- Exponer variables de sesiones activas al contexto de Continue
- Actualizar en tiempo real

## 7. Riesgos y Mitigaciones

| Riesgo | Mitigación |
|--------|------------|
| Continue actualiza y rompe nuestros cambios | Fork mantenido o patches automatizados |
| API de Positron cambia | Usar solo API estable, wrappers defensivos |
| Performance lento | Ejecución async, no bloquear UI |
| Compatibilidad con VS Code vanilla | Siempre tener fallback a comportamiento original |

## 8. Definición de Hecho (DoD)

- [ ] Continue detecta Positron automáticamente
- [ ] Código R se ejecuta en Consola de Positron (no terminal genérico)
- [ ] Código Python se ejecuta en Consola de Positron
- [ ] Gráficos aparecen en panel Plots de Positron
- [ ] Variables de sesión son visibles para Continue
- [ ] Fallback a terminal funciona si Positron no está disponible
- [ ] Todo commiteado y respaldado en git
